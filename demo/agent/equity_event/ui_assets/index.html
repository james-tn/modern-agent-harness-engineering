HARNESS COMPONENTS

Fix the task; choose how the model runs.

Deployment & fixed runtime
  • Fixed goal and instructions. Analyze the synthetic ACX earnings event and produce an evidence-backed briefing. Keeping the task fixed makes profile comparisons meaningful.
  • One AgentSession per episode. Goal, constraints and plan persist across its turns without sharing a session between runs.
  • Native MAF OpenTelemetry is on. The local exporter keeps model spans, tool spans and custom events inspectable in the same trace.

BOUNDED AUTONOMY

Bound how long the agent can keep trying.

Budgets & execution boundary
  • Fixed arithmetic-only Python template. Restricts generated computation to the reviewed arithmetic boundary. Execution uses python -I; this is not an OS sandbox.
  • Fixed no-progress guard: 3 identical calls. Rejects the next identical call to stop repetition without progress; this limit is not configurable.

PROGRESSIVE TOOLING

Expose only the capabilities the task needs.

Available skills

available_skills filters the framework's skill catalogue. Discovery exposes names and descriptions; it does not load skill instructions.

Domain tools

enabled_tools controls optional domain retrieval and execution.

Removing retrieval or execution tools may leave the model unable to finish. Infrastructure tools are fixed, not toggles.

INTELLIGENT CONTEXT / CONTEXT HYGIENE

Carry useful context without treating memory as policy.

Memory scope & context behavior
  • Filtered synthetic source results. Only admitted research inputs enter model context, keeping withheld content out.
  • Compaction is OFF. No automatic trimming is wired; this runtime has no compaction setting to enable.
  • Memory is evidence, not policy. Retained observations cannot override current constraints.

ACCEPTANCE GATES

Separate proposed completion from independently accepted evidence.

Fixed checks & human approval
  • Mandatory policy is always on. Keeps data admission consistent across presets; it cannot be disabled.
  • 9 independent checks always run. Preserve independent failure observations in every mode. Observe mode never turns invalid output into a verified certificate.
  • Human approval is separate and unskippable for a verified certificate. A reviewer, not the model or passing checks, grants publication approval. No email is sent.
